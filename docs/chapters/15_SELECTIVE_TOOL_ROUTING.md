# Choosing and Combining the Tools

An archive assistant may receive a request to quote the current access rule, another to compare copy-based and original consultation, and a third to explain why an apparently approved visit still cannot proceed. The subject is the same collection. The work required is different.

Loading every cognitive module for each request would obscure that difference. **Cognitive Tools Probe Profiles** supplies a routing layer: briefly inspect whether a module could change the next decision, preserve the useful compact result, and deepen the work where its contribution is material. The aim is the smallest useful route with enough grounds to revisit its choices.

## 1. Identify what remains to be done

Begin with the request and the evidence already available. If the user supplies the current permission text and asks which clause concerns supervision, the task may require a direct reading. An elaborate exploration of archive policy would add a different inquiry.

If the user instead asks which access arrangement serves a particular research question, the answer depends on the evidence that question requires, the available carriers and the governing conditions. If those are clear and one route satisfies them, further branching may add little. Several materially different surviving arrangements create a reason for comparison.

The distinction can be expressed through a few requests:

| Request | Consequential work |
|---|---|
| Identify the supervision clause in supplied rules. | Retrieve and interpret the relevant text. |
| Compare two supplied access arrangements. | Examine their different consequences and requirements. |
| Repair an original-consultation plan with a missing permission step. | Trace the ordered dependencies. |
| Review a rejection that treated all copies as inadequate. | Inspect the selection grounds and scope of pruning. |

*Abstraction* identifies the kind of unresolved work. *Classification* relates it to a tool's role. *Comparison* asks whether that role could change the result. Together they select a method on a functional basis. Shared vocabulary such as “access” is insufficient to determine the route.

## 2. Distinguish four routing decisions

A probe is a compact classification and handoff operation. It does not perform the full work merely by predicting that the work is needed. The source defines four decisions:

| Decision | Meaning in the archive case |
|---|---|
| `suppress` | Skip full KCE extraction when the objective is explicit and uncontested. |
| `emit_probe_only` | Retain a compact account of known roles or constraints when that is enough for the next handoff. |
| `escalate_full` | Run PSPP when materially different access arrangements require a defensible selection. |
| `switch_strategy` | Obtain the missing permission text or an appropriate inspection when reasoning cannot supply the required input. |

Suppressing KCE does not discard the goal. The compact anchor—meaningful study while preserving the collection—can remain available without being extracted again. Likewise, a compact regime account can retain that original handling requires permission and suitable conditions without expanding every possible operating regime.

Switching strategy is especially consequential. If the decision turns on whether an image preserves a faint mark, generating more policy alternatives cannot establish its legibility. The next useful act is an appropriate inspection, or a conditional answer identifying the missing finding.

*Decomposition* separates routing from execution. *Evaluation* asks what the available inputs support. Their combination prevents a small routing judgment from being mistaken for the comparison, validation or factual check it recommends.

## 3. Keep a reason for what was skipped

Selective work needs a record of selection. The probe contract carries the decision, confidence, expected gain, estimated cost, input availability, minimal outputs and a handoff target. It also records what was kept or suppressed and why.

The compact **audit stub** gives that record practical value. Suppose ETE is suppressed because the supplied alternatives are already materially distinct and sufficient for the requested comparison. The stub can retain that basis, name the risk of skipping further exploration, and specify a reopening condition: the comparison finds that none serves the research requirement.

This is more useful than recording “ETE unnecessary.” It tells the next agent what would make that judgment obsolete. A later failure need not trigger a complete restart or inherit the old suppression unchanged.

*Relation extraction* connects a routing choice to its grounds. *Concretization* names an event that would change it. *Evaluation* supplies the recheck. Their combination makes economy accountable: the application can inspect why work was omitted and when to restore it.

In the source protocol, high suppression risk, suspected pruning loss, suppressed anchor or return-path details, and possible false harmony require DARE review. A brief handoff should therefore preserve the material difficulty even when it omits a long trace. Compression cannot justify removing the very requirement needed to judge the answer.

## 4. Combine contributions through their dependencies

Once the needed work is clear, tools can be combined according to what each result supplies. In the archive, ETE can develop candidate arrangements when none is adequate yet. PSPP can compare the resulting candidates. CEC can examine an ordered permission and handling path when that order affects validity. DARE/IDCM can inspect a fragile selection or consequential rejection.

CREM becomes useful if the unresolved issue concerns how coherent parties' requirements and shared dependencies relate. Its presence is not established merely because two people participate in a consultation. Similarly, CEC need not expand an obvious step simply because the answer contains verbs in an order.

This permits different bounded routes. A comparison of supplied candidates can begin with those candidates and their requirements. A request to repair a known missing step can focus on CEC. A request to reconsider a discarded alternative can focus on DARE/IDCM and return a justified rescue to the comparison. Each route preserves the original concern and supplies whatever the next act actually needs.

*Sequencing* arranges dependent contributions. *Recombination* joins compatible results. *Evaluation* checks the connection back to the task. Together they add coordination without requiring every tool to participate.

The architecture reference lists a broad execution order and the probe file supplies several stack presets. These express conditional responsibilities; the book's chapter order is not an execution requirement. A capable model may also use the useful strategy of a selected method within one response; an application needs explicit orchestration when separate calls, artifacts or checks must be managed.

## 5. Escalate, stop, and retain a way back

A probe earns escalation when fuller execution can change the route, distinguish candidates, prevent an invalid answer or preserve a needed return path. The source reserves full mode for substantive outputs such as durable artifacts, final synthesis and deep validation. Within that protocol, a probe's recommendation is a handoff to the work that establishes the result.

The numerical thresholds in Probe Profiles are design controls. For example, its shared expected-gain threshold for full escalation is 0.62. That number specifies a policy boundary; it does not demonstrate measured benefit or calibrate a model's confidence. A useful explanation still names the difference the deeper work could make.

Stopping also follows the task. If an adequate copy is established for the wording request and no competing condition changes the decision, further exploration can stop for that request. The binding request can remain unresolved with its missing dependency stated. Retaining that distinction is part of completion.

A bounded request exposes the routing discipline:

> Choose the smallest useful cognitive-tools route for this archive request. Use the supplied objective, candidates, permissions and findings; mark absent inputs. For each considered module, suppress it, retain compact probe output, escalate to full execution, or switch strategy. Give a short reason tied to what could change the answer. Preserve required handoff fields, suppression risks and recheck triggers. Use only the conditional probes the task needs. Carry unresolved facts to the next act and stop when the requested result and its limits are established.
