# PSPP: compare candidates before selecting a conclusion

**Question:** Which candidate survives the evidence and constraints, and what would change that choice?

## The problem and the method

Generating alternatives does not ensure that they receive a meaningful comparison. A model can prefer the most polished account, dismiss an inconvenient branch without a reason, or merge positions whose important differences should remain.

PSPP normalizes candidate systems, identifies duplicates, applies relevant checks and records selection, merge or deferral decisions. It retains the direct interpretation unless that branch fails materially. Verification should discriminate between survivors rather than add reassuring prose.

## Historical development

Parallel problem-solving preceded the current comparator. The surviving v4.0 description, discussed in April 2026, shifted attention from alternative answer framings to candidate constructed systems and incorporated ordered path checks.

The May 2 refactor made PSPP v5.0-lite primarily a comparator: ETE explores and transforms; PSPP compares. The package also assigns relationship rebase to CREM and conditional path validation to CEC, reducing duplicated work.

## Example and boundary

If a delay could arise from competence, parts or permission, a useful comparison asks which observations distinguish those explanations. A highly fluent narrative does not compensate for a contradiction with the evidence.

A selection can be provisional, merged with explicit conditions, or deferred. The numerical scoring fields in the specification are proposed controls; a model filling them in does not create calibrated measurements. PSPP structures judgment, while evidence and task-specific tests remain decisive.
